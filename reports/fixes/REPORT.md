## 집중 타이머와 시간 표시

- 명시적 실행/일시정지 상태와 실제 시간 체크포인트를 사용한다. 가상 계획 시계 이동은 측정값에 더하지 않는다.
- 키보드·마우스 입력이 없는 독서도 타이머가 실행 중이면 측정한다.
- 재접속 또는 60초를 넘는 측정 공백은 자동으로 추정하지 않고 일시정지한다. 기존 측정값을 보존하고 종료 시 확인·수정할 수 있게 한다.
- 예정 시작·종료, 실제 시작·경과, 측정 집중 시간을 나눠 표시한다. 작업 완료/미완료 판단과 집중 타이머 일시정지는 서로 다른 상태다.
- 1분 미만 작업도 저장할 수 있도록 실제 시작·종료 입력은 초를 보존한다. 타이머는 24시간을 넘어도 0으로 돌아가지 않는다.

## 검증

`node --test tests/flowweek.test.js`: **53개 통과**. 기존 38개 검사 중 ‘매일 루틴은 무조건 이동 금지’라는 잘못된 기대를 수정하고 15개 회귀 검사를 추가했다. 추가 검사는 적립, 과거 예약, 과거 기록과 실행 분리, 지연 수행, 집중 타이머, 전환 원자성, 날짜 교집합, 미리보기, 데이터 이전 및 초 단위 기록을 포함한다.

별도 테스트 origin `http://127.0.0.1:4175`에서 제품 UI로 확인한 경로:

1. 첫날 기상 폼에 집중 입력이 없음을 확인하고 저장.
2. 예정 작업 시작 → 타이머 일시정지·재개 → 예정 종료를 넘겨 계속 실행.
3. 작업 전환 시 추가 예상시간 누락 오류가 원래 폼에서 표시됨. 추가 입력 후 후보로 이동하고 이전 버튼으로 값 보존 확인.
4. 현재 고정 일정으로 전환 → 집중 입력 없이 일정 종료.
5. 보상활동의 현재 이후 후보 확인 → 변경될 작업·시각 미리보기 → 적용 및 실행.
6. 보상활동을 유지하면서 이전 점심 기록을 확인. 현재 실행이 유지되고 미확인 항목만 제거됨.
7. 밤 휴식 → 취침으로 직접 전환 → 둘째 날 기상.
8. 둘째 날 00:00~07:10 수면 표시와 전날 23:10~00:00 표시, 전날 다른 실제 기록 조회 확인.
9. 둘째 날 루틴 타이머 시작·재개·일시정지 및 새로고침 후 측정값 보존 확인. 장시간 브라우저 측정 공백의 자동 일시정지도 관찰됨.

브라우저 오류 로그 조회 결과 오류 0건. 최종 화면 증거: `focus-timer.png`.

이는 가상 날짜를 이동한 기능·회귀 검증이다. 현실에서 48시간 연속 대기한 테스트나 다중 사용자 사용성 조사는 아니다.

## 데이터와 정책상 한계

- 저장 버전 1을 2로 명시적으로 이전한다. 과거 생활 기록과 작업 성과를 보존한다. 무효일 수 있는 예전 적립 대기 제안은 해제한다.
- 이전 버그로 이미 적립된 양은 당시 실제 행동을 확정할 근거가 없어 소급 차감하지 않는다. 앞으로의 잘못된 적립을 차단한다.
- ‘추가로 확보한 시간’은 작업을 앞당겨 배정한 시간이다. 실제 집중 성과나 별도의 보상 화폐가 아니다. 보상활동의 가능 여부는 실제 미래 자유시간과 제약으로 판단한다.
- 배치기는 제약을 검사하는 휴리스틱이다. 유효한 배치를 찾지 못하면 작업량을 잃는 대신 변경을 거절한다. 모든 가능한 일정 조합 중 최적해를 보장하지는 않는다.
- 브라우저 종료·절전 중의 집중 여부를 자동 판정할 수 없다. 과대 측정을 피하기 위해 해당 공백은 사용자가 종료 화면에서 확인한다.
