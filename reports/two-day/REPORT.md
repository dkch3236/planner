# FlowWeek 이틀 연속 사용자 시나리오 테스트

테스트 대상: 현재 작업 폴더의 FlowWeek. 제품 코드는 수정하지 않고 실제 화면을 조작해 평가했다.

**결론: 개별 상태 전이는 상당 부분 작동하지만, 하루를 넘겨 연속 사용하면 시간의 유효성·자유시간 보상·기록 조회·전환 동선에서 문제가 발생한다. 현재 상태를 편안하게 매일 쓸 수 있는 단계로 보기는 어렵다.**

## 방법과 범위

- 가상 날짜: 2026-09-28 월요일~09-29 화요일. 전날 23시 수면을 사전 조건으로 두고 첫날 07:30 기상부터 둘째 날 23:10 취침까지 이어서 실행했다.
- 실제 앱의 가상시계를 사용했다. 현실에서 48시간 대기한 테스트나 여러 사람을 대상으로 한 사용성 조사는 아니다.
- 별도 origin `http://127.0.0.1:4174`를 사용했다. 기존 `4173` 브라우저 기록과 localStorage를 공유하지 않는다.
- 별도 서버는 최초 데이터만 주입한다. 그 이후 화면·액션·스케줄러는 제품 소스를 그대로 사용한다.
- 브라우저 화면 상태 52개, 증거 스크린샷 11개를 저장했다.
- 발견사항 중 핵심 7건은 DOM과 별개로 도메인 코드에서도 재현했다. 추가로 전환 실패 시 원본 상태 보존을 확인했다.
- 기존 자동 테스트 38개는 여전히 통과했다. 기존 테스트의 통과가 연속 사용성의 완성도를 보장하지 않는 사례다.
- 수동 종료 때 순공을 직접 입력했다. 가상시계와 실제 stopwatch가 분리돼 있으므로 가상 1시간 이동 후 측정 순공이 0분에 가까운 것은 이번 테스트의 오류로 간주하지 않았다.
- 52개 화면 검증 시점의 브라우저 JavaScript 오류는 0개였다. 마지막 데이터 내보내기의 자동 다운로드 이벤트 수신은 도구 제한 시간 내 완료되지 않아 성공 여부를 판정하지 않았다. 아래 제품 오류 목록에는 포함하지 않았다.

## 우선 수정할 기능·정책 문제

### 1. 과거 시간을 ‘나중에 하기’로 추천하고 예약도 받아들인다 — P1

- **재현:** 둘째 날 15:55 작업 종료 → 18:00으로 이동 → 보상활동 ‘영화 보기 90분’ → `15:55~17:25에 하기` 선택.
- **결과:** 저장 안내는 나오지만 이미 끝난 시각이라 미래 일정에 나타나지 않는다. 도메인 검증에서는 `personalPlans`에 남고 미래 블록·미확인 목록에는 없었다.
- **사용자 느낌:** “예약했다고 했는데 내 일정은 어디로 갔지?”
- **개선:** 후보 시작을 `max(now, freeStart)`로 계산하고, 액션 단계에서도 과거 예약을 거절한다. 저장한 시간과 위치를 피드백으로 보여준다.
- 근거: `ui/modals.js` reward 후보 생성, `domain/actions.js` REWARD 시간 검증. 도메인 재현 F05.
- [화면 증거](screenshots/11-reward-offers-past-time.png)

### 2. 미완료로 남긴 작업을 ‘조기완료 자유시간’으로 보상한다 — P1

- **재현:** 첫날 09시 발표 작업, 09:25에 25분 순공으로 미완료 종료 → 이메일 당기기.
- **결과:** 발표는 65분 남았는데 ‘조금 일찍 마쳤네요’, ‘35분 모을 수 있어요’를 표시하고 실제 +35분 적립한다.
- **사용자 느낌:** “덜 했는데 시간이 생겼다고? 이 숫자를 믿어도 되나?”
- **개선:** 성공적 조기완료와 미완료 중단을 분리한다. 다른 시간에 해야 할 잔여 작업을 추가 자유시간의 순증가로 계산하지 않는다.
- 근거: `domain/execution.js` pendingSaved 생성이 DONE 여부를 검사하지 않음. `scheduler/replan.js` 그대로 Credit 반영. 도메인 재현 F01.
- [화면 증거](screenshots/02-incomplete-called-early-completion.png)

### 3. 조기종료 선택 안내가 만료되지 않아 다음 일정을 가린다 — P1

- **재현:** 둘째 날 07:30 종료 후 선택하지 않고 09:00까지 이동.
- **결과:** 09시 루틴 시각에도 현재 카드가 ‘조금 일찍 마쳤네요’인 FREE 상태다. 한참 쉬고 돌아와도 Credit을 받을 수 있었다. 추가 도메인 검증에서는 11시 고정 미팅도 이 안내에 가려졌다.
- **사용자 느낌:** “지금 해야 할 일이 무엇인지 앱이 계속 옛날 이야기만 한다.”
- **개선:** `pendingSaved.until`로 만료시키고, 현재 고정 일정·수면 안내보다 오래된 선택이 앞서지 않도록 한다. 즉시 다음 일을 한 경우에만 이동 가능한 시간으로 계산한다.
- 근거: `scheduler/currentView.js`의 무조건적인 pendingSaved 우선 분기. 도메인 재현 F02.
- [화면 증거](screenshots/08-expired-early-finish-prompt.png)

### 4. 밤새 잔 기록이 아침 주간에서 보이지 않고, 어제 기록에도 돌아갈 길이 없다 — P1

- **재현:** 23:10 자러가기 → 다음 날 07:10 기상 → 주간.
- **결과:** 수면 데이터는 존재하지만 시작 날짜가 어제라는 이유로 오늘 열에 표시하지 않는다. 빈 구간 계산에는 수면이 반영돼 00~07:10이 미기록으로도 나오지 않는다. 화면은 오늘 07:10부터 시작한다.
- **추가 불편:** 주간은 오늘부터 미래 7일뿐이고 별도 과거 기록 조회 화면이 없어 어제의 기록을 수정·검토하기 어렵다. rolling 7일 자체는 요구사항대로지만 과거 기록 탐색 기능이 보완돼야 한다.
- **개선:** 자정을 넘는 실제 구간은 날짜 경계에서 표시용으로 분할한다. 저장 레코드를 쪼갤 필요는 없다. 오늘+6일 주간은 유지하면서 과거 기록 조회를 별도로 제공한다.
- 근거: `ui/views.js`의 `day(t.start) === d` 필터. 도메인 재현 F03.
- [화면 증거](screenshots/06-overnight-sleep-not-visible.png)

### 5. 일일 루틴을 언제나 ‘마지막 기회’로 취급해 충분히 가능한 보상 재배치를 막는다 — P1

- **재현:** 둘째 날 07:10, 현재 여백 110분 → 120분 아침 요리 요청. 영어는 09~21시 사이 20분 수행 가능.
- **결과:** 영어를 조금 늦추면 되는데 ‘루틴의 마지막 수행 기회는 옮길 수 없어요’로 차단한다. 도메인 검증에서 보상 이후 영어를 합법적으로 배치할 수 있음을 확인했다.
- **사용자 느낌:** “저녁에도 충분히 할 수 있는데 왜 지금 못 쉬게 하지?”
- **개선:** 주기의 마지막 **날짜**인지가 아니라, 다른 합법적 수행 **구간**이 남아 있는지 판단한다.
- 근거: `scheduler/replan.js`에서 `window.end === today`만으로 거절. 도메인 재현 F04.
- [화면 증거](screenshots/07-routine-last-chance-overblocking.png)

### 6. 마감이 지난 일은 계속 남아 있지만 ‘늦게라도 지금 하기’가 없다 — P1/정책

- **재현:** 첫날 미완료 이메일 15분 → 둘째 날 가능한 시간대 09시 후보 확인, 15:35 상세 확인.
- **결과:** ACTIVE 목록에는 남지만 시작 후보에 없고 상세에도 시작 버튼이 없다. 원래 마감을 오늘로 바꾼 뒤에만 시작할 수 있었다.
- **사용자 느낌:** “늦었지만 해야 하는 일을 하려면 마감 기록부터 고쳐야 한다.”
- **구분:** 기존의 마감 제약을 엄격히 지킨 결과다. 데이터 계산 오류보다는 사용자의 실제 선택을 수용하지 못하는 정책 문제다.
- **개선:** 원래 마감을 보존한 채 ‘지연 수행’, ‘마감 재협의’, ‘포기’를 명시적으로 선택하게 한다.
- 근거: `scheduler/availability.js` deadline 상한과 candidates 검사. 도메인 재현 F07.

## 반복 사용을 불편하게 만드는 동선·문구

### 7. 전환 오류가 난 화면에서 필요한 값을 수정할 수 없다 — P2

발표 20분을 수행하고 ‘다른 작업으로 전환’ → 순공 20분만 입력 → 논문 선택하면 추가 남은 시간을 요구한다. 그런데 화면은 이미 후보 목록이라 입력란도 뒤로 버튼도 없다. 모달을 닫고 처음부터 입력해야 했다. 후보 화면으로 넘기기 전에 현재 작업 종료값을 검증하거나, 입력값을 보존한 뒤로 가기를 제공해야 한다. 실패 시 실행·작업량이 보존되는 점은 정상이다.

### 8. 현재 작업을 켜 놓으면 서로 겹치지 않는 과거 기록도 확인할 수 없다 — P2

### 9. 수면·휴식·보상까지 작업 완료용 화면을 사용한다 — P2

기상에 ‘확인한 순공시간’, ‘할당 작업량을 반영합니다’가 나온다. 쉬는 중에도 ‘나에게 집중하는 시간’, ‘다 했어요’, ‘미완료로 끝내기’를 보여준다. 취침시간이 되어도 쉬는 상태에서는 자러가기가 없어 휴식을 끝내고 다시 자러가기를 눌러야 한다. 활동 종류별 종료 문구·필드를 나누고 ‘휴식 마치고 자러가기’를 제공하는 편이 자연스럽다.

### 10. 미팅 시간 경고는 있지만 그 미팅으로 바로 전환할 수 없다 — P2

### 11. 일을 뒤로 밀고 쉬고 싶을 때 보상활동 버튼이 오히려 숨겨진다 — P2

첫날 13시 발표가 현재 계획으로 표시되자 ‘보상활동 하기’가 없었다. 미래 FREE 블록 → 상세 → 보상활동 계획 → 입력이라는 우회 경로가 필요했다. 현재가 planned 상태여도 ‘대신 하고 싶은 활동’을 고를 수 있어야 미래 여백 당기기를 발견하기 쉽다.

### 12. 재배치 전 무엇이 얼마나 바뀌는지 보이지 않는다 — P2

베이킹 모달에는 부족한 시간과 실행 버튼만 있고, 발표·논문이 언제로 옮겨지는지 보여주지 않는다. 버튼을 누르면 재배치와 실행이 동시에 일어난다. 실제 테스트에서 발표가 13시에서 17:10으로 이동했다. 사용자는 뒤늦게 오늘 흐름을 읽어야 알 수 있다. 변경 전후 시간, 마감 영향, 보호된 일정을 보여준 후 ‘이 계획으로 시작’하게 하는 것이 좋다.

[화면 증거](screenshots/03-reward-no-change-preview.png)

### 13. ‘다 했어요’가 전체 Todo 완료인지 이번 세션 완료인지 불명확하다 — P2

발표를 오래 수행한 후 ‘다 했어요’를 눌렀는데 관리에는 20분이 남았다. **할당 작업량을 차감한 계산은 요구사항대로 정상**이다. 다만 실행 화면에는 이번 할당량·전체 남은 양이 보이지 않아 사용자는 전체 완료로 이해하기 쉽다. ‘이번 45분 분량 완료’와 ‘할 일 전체 완료’를 구분하고, 종료 후 ‘남은 20분은 17:10 예정’ 같은 결과를 보여주면 이해하기 쉽다.

### 14. 성취 피드백과 사용자 언어가 부족하다 — P3

모든 일을 끝낸 관리 화면이 ‘아직 할 일이 없어요. + 버튼으로 추가해 보세요’라고 안내했다. 완료 목록도 완료 시각보다 ‘0분 남음’을 강조한다. 상세에는 `SHOULD`, `WINDOW` 같은 내부 용어가 그대로 보인다. ‘계획한 할 일을 모두 마쳤어요’, ‘오늘 완료 5개’, ‘중요도: 하면 좋음’, ‘가능한 시간: 09~18시’처럼 사용자에게 의미 있는 정보를 표시하는 편이 좋다.

## 정상 동작한 부분

- 예상 예약시간이 지나도 Execution을 자동 종료하지 않았다.
- 작업량과 벽시계 시간이 섞이지 않았다. 완료는 할당 작업량, 미완료는 확인 순공을 차감했다.
- 전환 시 이전 작업의 남은 양을 갱신하고 새 실행을 하나만 생성했다.
- 전환 실패 시 원본 실행·요구량을 보존했다.
- 실제 기록을 수정하고 낮잠을 추가할 수 있었으며 Todo 성과와 분리됐다.
- 자유시간을 이동해 첫날 베이킹 60분을 수행하는 경로는 성공했다.
- Credit이 없어도 보상 후보를 제시했다. FREE 위치와 Credit 수치를 따로 표시했다.
- Routine 최소버전과 정규 버전 모두 완료 횟수에 반영됐고 다음 날 다시 제안됐다.
- 확인한 항목은 미확인 모달에서 즉시 사라졌다.
- 완료된 Todo는 활성 관리 목록에서 사라지고 완료 목록에서 조회됐다.
- 취침시간만으로 수면을 자동 시작하지 않았고, CLOSED 수면을 자동 재오픈하지 않았다.

## 수정 순서 제안

1. **시간 유효성:** 과거 보상 예약 거절, 만료된 pendingSaved 제거. 잘못된 현재 안내와 보이지 않는 예약을 먼저 막는다.
2. **자유시간 신뢰성:** 미완료 적립 방지, 실제 남은 루틴 기회 판단.
3. **기록 가시성:** 자정 경계를 넘는 기록 표시, 과거 날짜 기록 조회.
4. **중단 없는 행동:** 지연 수행, 과거 확인과 현재 실행 분리, 전환 오류 복구.
5. **작은 동선과 문구:** 활동별 종료 화면, 미팅/취침 바로 전환, 보상 변경 미리보기, 완료 피드백.
