# 개발용 에셋 생성

## 실행

프로젝트 폴더에서 Windows 실행 파일을 사용합니다. 현재 환경에 설치된 Python을 우선 사용하고, Pillow가 없는 경우에만 `python -m pip install Pillow`를 실행합니다.

```powershell
.\scripts\prepare_assets.cmd --input "$env:USERPROFILE\Downloads\assets.zip"
```

일반 Python 환경(Python 3.10 이상, Pillow의 WebP 지원 필요):

```text
pip install Pillow
python scripts/prepare_assets.py --input /path/to/assets.zip
```

ZIP 대신 이미지 폴더도 입력할 수 있습니다. 작업 디렉터리와 무관하게 기본 출력 위치는 이 프로젝트의 `public/assets`, 검수 자료는 `reports/assets`입니다. 원본 파일은 수정하거나 덮어쓰지 않으며 ZIP은 압축 해제 없이 읽습니다.

## 분리 방식

1. 알파 마스크에서 8방향 연결 성분을 찾아 바운딩 박스를 구합니다. 검출 코드는 Pillow와 Python 표준 라이브러리만 사용합니다.
2. 제공된 파일에는 배경 알파 1~수십 수준의 잔여값과 잡점이 있습니다. 그대로 `alpha > 0`을 연결하면 일부 시트 전체가 하나가 됩니다. `asset_rules.json`에 기록한 탐지 임계값과 최소 성분 면적으로 잡점을 제외합니다.
3. 탐지된 윤곽 주변 2픽셀은 원본 알파를 보존하여 가장자리를 유지합니다. 그 밖의 잔여 배경은 투명하게 만듭니다. 원본 색상은 다시 칠하지 않습니다.
4. `character/growth/level/rest`는 단독 일러스트로 취급해 떨어진 꽃잎·별도 함께 보존합니다. 아이콘은 투명한 행·열 간격으로 묶어서 음표나 꽃잎을 분리하지 않습니다. 일반 시트는 연결 성분을 사용하고 작은 인접 장식만 큰 객체에 붙입니다. 큰 객체끼리는 바운딩 박스가 겹친다는 이유로 합치지 않습니다.
5. `corners_borders`에는 흐릿한 선과 떨어진 장식이 많아 시트 구조에 맞춘 영역 가이드를 설정했습니다. 가이드 내부의 실제 크기는 알파로 자동 탐지하며, 가로 보더는 행 단위로 보존합니다. 가이드는 기준 해상도에 비례하여 적용합니다. 다른 구조의 새 시트에는 이 규칙을 수정해야 합니다.

정확히 알파 0만 공백으로 취급하고 잡점 제거·의미상 그룹화를 모두 끄려면 **다른 출력 폴더에** 실행합니다. 제공된 파일에서는 이 모드가 미세 잡점도 수백 개씩 추출하거나 일부 시트를 한 덩어리로 만들 수 있습니다.

```text
python scripts/prepare_assets.py --strict-alpha --output public/assets_strict --report reports/assets_strict
```

## 표준 크기와 폴더

| 종류 | 출력 규격과 위치 |
| --- | --- |
| 아이콘 | 잘라낸 원본의 긴 변에 가장 가까운 32·48·64px 정사각형. 고해상도 아이콘 시트는 64px. `icons/32`, `icons/48`, `icons/64` |
| 긴 가로 에셋·보더·코너 프레임 | `borders`. 긴 변을 32~512px 표준값에 맞추고 짧은 변은 비율을 반영하여 8px 단위로 올림 |
| 단독 캐릭터 | `characters`, 512×512 |
| 성장·레벨·휴식 일러스트 | `illustrations`, 성장·레벨 256×256, 휴식 512×512 |
| 테이프·우표·기타 장식 | `tapes`, `stamps`, `decorations`. 원본 비율에 따라 표준 사각 캔버스 |

모든 리사이즈는 LANCZOS입니다. 가로·세로를 같은 배율로 변경한 뒤 투명 캔버스 중앙에 배치합니다. 비율을 늘려 맞추지 않습니다. 파일명은 `icon_icons_1_001.webp`, `border_corners_borders_001.webp` 등 종류·원본명·순서로 구성합니다. 모든 배포 이미지가 알파를 지원하는 **무손실 WebP**입니다.

## 확인과 재실행

- `reports/assets/catalog.html`: 필터 가능한 전체 검수 페이지. ‘검토 필요’를 검색하면 작은 조각이나 맞닿은 그림 후보를 확인할 수 있습니다.
- `reports/assets/sheets/*.jpg`: 원본 위에 추출 번호와 바운딩 박스를 표시한 검수용 이미지. 개발용 배포 에셋이 아닙니다.
- `reports/assets/contact_*.jpg`: 종류별 미리보기.
- `public/assets/manifest.json`: 원본 SHA-256·해상도, 추출 좌표·크기, 출력 캔버스·콘텐츠 크기·중앙 여백, 분류, 용량, 검토 후보 목록.
- 생성 후 모든 WebP를 다시 읽어 크기·비어 있지 않은 알파·저장 전 픽셀과의 일치를 확인합니다.
- 재실행 시 이전 manifest에 기록한 생성 파일만 갱신하고, 더 이상 생성되지 않는 옛 결과만 제거합니다. 그 밖의 기존 파일은 덮어쓰지 않습니다. 수동 편집한 생성물을 유지하려면 다른 폴더로 복사하거나 `--output`을 바꾸세요.
- 붙어 있거나 실제로 겹쳐 그려진 객체는 알파만으로 완벽하게 복원할 수 없습니다. 그런 경우 합성된 상태를 유지하고 검토 후보로 표시합니다. 의미상 모든 객체를 완벽하게 판별하는 모델은 아닙니다.

알고리즘 검사: `python scripts/test_prepare_assets.py`.

## 수동 검수 반영 (2026-09-27)

`asset_review.json`은 원본 번호 기준 삭제 86건과 보정 7건을 보존합니다. 자동 추출 뒤 검수 규칙을 적용하므로 다른 에셋 번호는 바뀌지 않습니다. 두 그림을 분리한 025·071·097은 기존 이름에 `_left`, `_right`를 붙입니다. 문장부호의 점은 원본의 분리된 영역을 포함해 복원하고, 주변 그림 혼입은 선택 영역의 주된 연결 객체만 남겨 제거합니다. 글자는 지정 영역의 알파를 지웁니다. 원본 ZIP은 변경하지 않습니다.

좌표가 다른 원본에 적용되는 것을 막기 위해 원본 SHA-256과 기존 추출 좌표를 검증합니다. 원본이나 추출 규칙이 바뀌면 재검수 후 규칙을 갱신해야 합니다. `--strict-alpha`에서는 이 검수 정책을 적용하지 않습니다. 최종 manifest의 `review_decisions`에서 삭제·교체 내역을 확인할 수 있습니다. `sheets` 이미지는 자동 추출 단계의 번호 참고용이며 최종 결과는 catalog와 contact 이미지에 표시됩니다.

## 처리 완료 에셋 추가 (2026-09-28)

`python scripts/import_ready_assets.py --input <asset_처리전.zip 경로>`로 추가합니다. 이 경로는 투명도 처리·크롭·분리·리사이즈·패딩을 전혀 적용하지 않고 원본 크기의 무손실 WebP로 변환합니다. 디코딩한 RGBA 픽셀이 원본과 동일한지, 기존 에셋의 SHA-256이 유지되는지 검사합니다.

- `icons/illustrated`: 그림형 아이콘 29개. 작은 32/48/64px 아이콘과 구분하고 원본 해상도를 보존합니다.
- `backgrounds/landscape`, `backgrounds/portrait`: 가로 배경 5개, 세로 배경 8개.
- `overlays/weather`: 가로 날씨 오버레이 6개. 투명도를 그대로 보존합니다.
- `borders`: 보더·코너 5개와 icons 폴더에 있던 긴 꽃 장식 1개.
- `textures/paper`: 종이 텍스처 4개.

한글 ZIP 파일명은 CP949를 고려해 읽습니다. 원본 경로·해시·분류·변환 방식을 manifest에 기록하며, 추가 묶음 소유권을 분리해 기존 추출 스크립트를 재실행해도 추가 파일이 삭제되지 않습니다. 추가 파일끼리의 갱신만 허용하고 다른 에셋과 이름이 충돌하면 중단합니다. 추가 목록은 `reports/assets/additions/catalog.html`에서 확인할 수 있습니다.

## 아이콘 이름과 화면 표시

기존 아이콘 190개의 의미 있는 파일명은 `icon_names.json`에 저장하며 자동 추출 후에도 적용합니다. `name_icons.py`로 기존 결과에 적용할 수 있습니다. `legacy_path`와 `icon_name_mapping`으로 이전 이름을 추적합니다. 같은 소재의 변형에는 숫자 접미사를 붙입니다. 흐릿한 작은 장식은 기능을 추측하지 않고 색·형태로 이름을 붙였습니다.

추가한 그림형 아이콘 29개는 원본 비율과 크기를 유지합니다. UI에서 일정한 표시 영역과 `object-fit: contain`을 사용하면 찌그러짐이나 배치 흔들림 없이 표시할 수 있으므로 이미지 자체에 정사각형 패딩을 추가할 필요가 없습니다. 세부 그림이 많으므로 16px 버튼용으로 무조건 축소하지 말고 화면에서 식별 가능한 크기를 선택하세요.

```css
.illustrated-icon {
  width: 64px;
  height: 64px;
  object-fit: contain;
  object-position: center;
  display: block;
  flex-shrink: 0;
}
```
